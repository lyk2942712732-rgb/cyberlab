## 后续桌面连接修复（2026-09-30）

原客户端在 WebSocket 握手中提供 `cyberlab-ticket` 和一次性票据，Nginx 将整项协议头清空，上游未选回浏览器提供的协议，导致连接失败。修复提交 `da88955` 改为客户端提供 `binary` 与票据；HTTP/HTTPS 网关只接受该格式，验证票据后向 websockify 传递 `binary`，并正常返回其选中的协议。票据仍不会转发给 Kali，也不写入 URL。

前端类型检查、生产构建及 HTTP/HTTPS Nginx 配置检查通过。Ubuntu 前端编译过慢，部署采用同提交在本机构建的 `dist`，配合原前端 Nginx 配置打包为镜像；生产后端和 Kali 镜像不变。

Edge 对实际 HTTPS 部署的必要验证通过：真实桌面像素、协商协议为 binary、主动断开后按钮重连、实验页 iframe 连接，以及已消费票据/无效票据拒绝。仅执行短交互验证，不进行长时间压测：两次纯键入到画面更新为 43ms、421ms；终端命令执行到画面变化另测为 2466ms、1726ms，包含命令执行及同步操作采集，不能与纯键入延迟混同。这些短测不代表所有负载下的延迟保证。

回归检查在 `frontend/e2e/desktop-connection.spec.ts`，使用 `CYBERLAB_DESKTOP_FIXTURE` 指向私有的 `{session_id,token}` 文件，针对专用已就绪实验运行。可选 `terminal_ready=true` 要求先打开最大化的专用终端并关闭光标闪烁，用两次纯键入测量响应。修复后旧页面需要重新加载才能使用更新的客户端协议。

### 当前实际结果与适用条件

10 月 3 日复测时 Ubuntu 刚重启，只有 Ubuntu 虚拟机运行；配置仍为 4 vCPU / 4GB、VMware 16.2.4、`Monitor Mode: ULM`。代码 `bb48227` 下，新建完整实验 API 到 READY 为 15.512 秒；部署 `f5b2767` 新 Kali 镜像后的新建实验为 12.323 秒，靶机访问、桌面和采集就绪均通过。

相同软件在 9 月 30 日的高负载运行状态下曾需 109–111 秒，因此不能把这次大幅改善全部归因于代码，也不能据此保证所有负载下都小于 30 秒。此前约 30% 的 CPU 等待压力、较高的后台服务 CPU 占用在这次重启后的采样中明显降低。尚未通过控制变量证明具体是哪个宿主机/虚拟机状态导致退化。

以下是 Edge 连接实际 HTTPS/noVNC 页面、应用实际 X11 窗口出现的短测；没有长时间压测。菜单和应用开启在 Firefox 已打开的桌面上测量；窗口切换另用两个应用窗口复核活动窗口 ID。

窗口切换复核同时确认 `_NET_ACTIVE_WINDOW` 确实改变且修饰键已释放。零间隔模拟 Alt+Tab 在 Openbox 中可能停留于选择框；因此原先只等待任意画面变化得到的 99/87ms 及旧基线不作为窗口切换完成时间。改为按键保持 100ms，并等待活动标题栏更新后核对实际窗口，避免把选择框显示误当成切换完成。该复核实验创建于 Ubuntu 启动约四小时后，完整 API 启动仍为 15.332 秒；此时菜单 40ms、应用查找器 588ms、终端 679ms，属于另一轮短测。

Firefox 新配置首次窗口出现的单项测量为 6.721 秒；最终功能验收中，首次打开到测试网页及浏览器采集均就绪为 9.417 秒。两者测量边界不同。首次启动 Firefox 仍有明显初始化等待，不能称为所有应用均瞬间打开。诊断时临时关闭无障碍功能的进程结果不作为正式性能结果，正式镜像继续启用无障碍与操作采集。
