# 实验结束后的 AI 复盘

这是面向实习作业的轻量实现：复用 FastAPI、PostgreSQL 和 httpx，通过一个独立 Python 进程读取数据库任务队列，调用 DeepSeek Flash。没有增加新的消息队列、向量数据库或 Agent 框架。

## 使用

学生结束实验、实验到期或环境创建失败后，编排服务在清理环境的同一事务中创建唯一的评估任务。会话页自动显示排队、生成中或报告；离开页面后，可从“我的成绩 → 实验复盘记录”进入最近 100 次结束的会话。

历史实验不会被批量自动送往模型。学生可在自己的已结束会话点击“生成实验复盘”。任务自动尝试最多三次，失败后可点击“重试生成”；当前格式的完成报告不会因重复点击而再次生成。旧格式报告可点击“更新报告”生成新版，保留原题解和证据快照；重复点击不会重复入队。管理员可读取和请求对应会话的报告，其他学生不能访问。

新版报告格式 `schema_version=2`，提示版本 4，包含简短结论、操作路径、连贯的可能思路、按证据选择的分项评价和最多三条改进建议。操作路径用 S 型有向图展示，节点名称与依据入口组成一个单位，悬浮、键盘聚焦或点按可查看说明；与旁边的思路段落一起折叠。窄屏时思路排在图下方。“查看依据”展示模型收到的脱敏事件或 Flag 判题结果。分项状态为已体现、部分体现、有待改进、暂无法判断，不计算 AI 总分，也不修改既有 Flag 成绩。

报告面向学生本人，称呼“你”，以完成结果、具体操作和可执行自检为主。事件编号只放在展开依据中，正文出现内部编号会触发重试。采集质量不算学生优点；未记录某步骤不直接评价为需要改进；已有正确 Flag 时明确肯定结果，不要求重复用其他工具证明。服务端修复默认作为原理自检或代码示意，除非实验明确提供实际修改条件。简单实验目标长度为 400—650 字，避免日志审计式说明。

## 评价设计依据

参考 [ETS 的证据中心设计](https://www.ets.org/research/policy_research_reports/publications/report/2013/jtcb.html)：评价结论需要可观察证据与合适的任务机会。结合 [EEF 的反馈指导](https://educationendowmentfoundation.org.uk/education-evidence/guidance-reports/feedback)，建议应针对具体表现，能引导下一步学习。这些是本项目的设计参考，并非对模型评价效度的认证。

| 维度 | 何时评价 | 不据此推断 |
| --- | --- | --- |
| 解题方法 | 核心项：输入、命令等是否针对实验问题 | 一次成功不等于独立掌握原理 |
| 结果验证 | 核心项：有无明确页面结果、正确 Flag 等 | 发出请求不等于执行成功 |
| 排查与调整 | 可选：有对照测试、参数变化或针对反馈的调整 | 缺少基线不等于能力差，重试次数不等于排查能力 |
| 原理解释 | 可选：有学生自己的解释、实际修复等直接证据 | 当前没有专门的解释入口，不能强行按每次操作评价原理理解 |

“正常行为基线”并非永远无法评价，但它只是排查策略之一；不再强制独立设项。可选维度没有证据时省略，不制造长期“证据不足”的格子。核心维度缺少结果时仍明确标为暂无法判断，避免隐藏未完成或不确定结果。

各栏目分工：路径只呈现事实，可能思路是一段有引用的推断，分项只判断对应表现，建议将问题与行动合成一句。取消独立优点和下一步栏目；相同建议合并引用，语义重复主要由提示约束减少。旧版报告保留兼容展示，但需更新生成才具备新的连贯推断与评价内容。

## 部署

迁移 `004` 添加 `lab_assessments` 表。配置仅写入服务器未跟踪的 `.env`：

```dotenv
ASSESSMENT_ENABLED=true
DEEPSEEK_API_KEY=填写自己的密钥
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

启动 Compose 的 `assessment` 服务，命令为 `python -m app.assessment_worker`。它与 backend/orchestrator 共用应用镜像，但单独运行、限制为 0.5 核和 384 MB，没有 Docker socket 或操作日志卷挂载。只通过内部编排接口读取采集。密钥仅传入 assessment 服务。

默认调用 `/chat/completions`，使用 thinking 的 high 强度核对操作语义与结论依据，生成上限 6000 tokens；只保存最终结构化反馈，不保存或展示模型的内部推理。模型及地址可配置；服务错误仅保存通用原因，不记录模型请求、响应正文或密钥。当前模型名及参数以 [DeepSeek 官方文档](https://api-docs.deepseek.com/guides/thinking_mode/)与模型列表为准，部署时已核对 `deepseek-flash`。

## 实现和边界

- 题解与实验目标在入队时快照保存，后续教师编辑不改变已有任务依据。
- 模型参考保留实验专属步骤、原理、失败原因与修复说明，省略题解末尾旧版“本实验评估要点”和“学习验收与评估约定”；评估规则由统一系统提示提供，避免旧固定量表与新版冲突。原题解和任务快照不修改。
- 按实际日志代次逐页读取，每页 100 条；证据编号为 `g代次:e序号`，判题编号为 `submission:UUID`。不能将最终会话 generation 当作日志目录。
- 只读取该会话的提交正确性、时间与 ID，不发送实际 Flag、账号或密码字段。
- 模型输入副本对常见敏感字段、URL 参数及编码参数、常见命令凭据做脱敏，保留实验用户名中引号和空格；不改写原始采集。自由文本的自动脱敏不是对任意秘密格式的完全保证。
- 初版最多读取 5000 条事件，模型最多使用 800 条、约 140000 字符的事件；优先保留网页与终端操作。超限会在报告中说明选取范围，不能声称完整还原。
- 一个模型请求完成过程解释和评价；Pydantic 校验 JSON，拒绝不存在的证据引用、重复维度或遗漏核心维度。路径和思路必须有对应引用；无引用的确定性分项改为证据不足，可选空维度省略。存在引用不代表模型解释必然正确，学生仍可展开依据核对。
- 没有任何操作或判题记录时生成明确的“证据不足”说明，不调用模型；采集读取失败会重试，不伪装成空记录。
- 采集通常不含终端输出与网页响应正文。模型被明确要求不把提交当作成功、不把推测当作真实心理；未记录解释与修复时无法确认理解程度。
- 评价方法时同时核对题解的常见失败原因，保留 SQL、命令等输入中有语义意义的空格与引号，区分错误输入和等价方法。提示约束不能完全消除模型误读。
- 任务每三秒检查一次。调用超时、格式错误、无效引用会有限重试；运行中断十分钟后恢复任务。单个进程串行处理，繁忙时会排队。没有承诺固定完成时间。

## API

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/lab-sessions/{id}/assessment` | 读取当前状态、完成报告与脱敏证据 |
| `POST /api/lab-sessions/{id}/assessment` | 已结束会话的首次请求或失败重试；其他状态保持幂等 |
| `GET /api/me/assessments` | 当前学生最近 100 次已结束实验与复盘状态 |

状态：`NOT_REQUESTED → QUEUED → RUNNING → COMPLETED`，失败有限重试后为 `FAILED`。

## 验证

`backend/tests/test_assessments.py` 覆盖手动结束/到期/失败自动入队、题解快照、权限、幂等重试、多代次分页、敏感信息副本脱敏、无效证据拒绝、真实请求格式和后台中断恢复。`frontend/e2e/assessment.spec.ts` 覆盖进度转报告、依据展示、历史入口、移动端和失败重试。
